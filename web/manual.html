sbm 管理手册

sing-box 节点、用户与订阅的管理说明。网页控制台能完成日常的所有操作，命令行作为补充。

  • 订阅服务器保存所有用户和节点信息，生成每个用户的订阅文件，并通过 SSH 把账号推送到各节点。用户的流量不经过订阅服务器。
  • 节点只负责转发流量。节点上的账号列表由订阅服务器统一管理，不要在节点上手动改 /etc/sing-box/config.json 的 users，下次同步会被覆盖。
  • 用户只需要一个链接（使用说明页），里面有订阅链接和各客户端的导入方法。客户端每 12 小时自动更新订阅，新增节点后用户无需任何操作。
为什么不用 443 端口：订阅服务器如果在中国大陆，未备案的域名不能使用 80/443 端口，所以订阅和控制台默认使用 8443（当前为 {{SUB_PORT}}）。云服务商的安全组必须放行这个 TCP 端口。

2. 用户管理

新增用户并发给对方

  1. 控制台右上角点 新增用户，填用户名（字母、数字、_ . -）和备注，点创建。
  2. 会自动弹出订阅窗口。第一项 使用说明页 就是要发给对方的链接：对方打开后能看到下载哪个客户端、一键导入按钮和操作步骤。
  3. 对方用手机的话，也可以直接扫窗口右侧的二维码。
新增用户立即生效，节点不重启。新用户使用的是账号池里的备用账号，这些账号早已在节点上，所以不影响任何正在使用的人。

以后要再次查看某个用户的链接，在用户列表里点 订阅 即可。备注可以随时点击修改，不会影响节点。

点用户的 配置 可以查看订阅的配置细节：「概览」列出节点、各代理组（默认选项高亮）、分流规则的匹配顺序和 DNS；另外三页是 sing-box / Hiddify、Clash Meta、通用链接实际下发给客户端的原文，密码默认打码，勾选「显示密码」才显示，可以复制或下载。帮用户排查「某个网站走了哪里」「导入报错」时很有用。

账号池与每日维护

sing-box 只在启动时读取用户列表，改动用户就必须重启，会让所有人断线几秒。为避免这一点，节点上始终预置了 20 个备用账号（用户列表标题旁的「账号池 19/20」）：

  • 新增用户：从账号池取一个，节点不变。
  • 停用/删除：账号先留在节点上（「待清理」），订阅立即失效。
  • 每天 04:00（北京时间） 自动维护：清理待清理账号、把账号池补满 20 个，并推送到节点。只有账号有变化的节点会重启，没变化的不动。

账号池用完（一天内新增超过 20 人）时，新增用户会提示需要重启节点，同时把账号池补满。想马上清理，可以点控制台顶部的 同步节点，效果和夜间维护一样。

地区组如何生成：按节点名称识别地区（不区分大小写）：HK/香港、TW/台湾、JP/Tokyo/日本、SG/新加坡、KR/韩国、US/美国 等；名称里的地区缩写要独立出现，例如 JP-Tokyo-01、US-LA-01。只有有节点的地区才会出现。给节点起名时按这个习惯即可，识别不到的节点只出现在「节点选择」里。

规则数据：统一使用 MetaCubeX/meta-rules-dat（sing-box 用其 .srs 规则集、Clash Meta 用同源的 geosite/geoip），由客户端通过节点自动下载和更新。Shadowrocket 拿到的是节点列表，使用 App 自带的分流规则。

查看实际内容：控制台里点任一用户的 配置，或命令行 sudo sbm user config 用户名。

修改分组：分组定义在 /usr/local/bin/sbm 的 REGIONS 和 SERVICES 里，改完运行 sudo sbm build 重新生成订阅即可，不会重启节点；用户的客户端下次更新订阅时生效。

流量统计

  • 控制台：顶部「本月流量」卡片是所有用户本月合计；用户列表的「本月流量」点一下可看该用户最近 30 天每日流量图、本月各节点分布、上月和累计；节点卡片显示该节点今日流量。
  • 客户端：订阅响应带有 subscription-userinfo，Clash、Shadowrocket、Hiddify 等更新订阅后会显示本月已用流量（没有设置上限，所以不显示剩余）。
  • 更新频率：每 5 分钟采集一次（定时任务 sbm-traffic.timer），按北京时间的自然日、自然月统计。

统计口径

统计的是节点与目标网站之间的流量，即用户实际上传、下载的数据（包含 TCP/TLS 包头，比文件本身大约多 1%~5%）。不包含客户端到节点那段 AnyTLS 加密的额外开销，所以会比服务商后台的服务器总流量略小。节点上其他程序产生的流量不计入任何用户。

原理（排查问题时参考）

官方 sing-box 没有按用户计数的功能。sbm 给每个节点账号生成一个专属出站（sbm-u-账号名，带唯一的 routing_mark）和一条按 auth_user 分流的路由规则；节点上的 /usr/local/sbin/sbm-stats 用 iptables 的 mangle 表（SBM_OUT / SBM_IN 链）按编号计数。这些出站和规则追加在节点原有规则之后，不要手动删除；如果节点上有自定义的分流规则，被它们分走的流量不会计入用户。

  • 节点重启或防火墙重载（如 CentOS 的 firewall-cmd --reload）会清掉计数规则，下次采集时自动补回，最多丢失几分钟的数据。
  • 节点卡片显示「统计异常」时，鼠标悬停可看原因；在节点上运行 /usr/local/sbin/sbm-stats read 可看原始计数。
  • 数据保存在订阅服务器的 /etc/sbm/traffic.db（已包含在第 7 节的备份命令里）。

命令行：sudo sbm traffic 查看本月各用户流量；sudo sbm traffic collect -v 立即采集一次。

3. 节点管理

一键部署新服务器

适合刚买的空白 VPS（Debian、Ubuntu、CentOS 等）。全程约 1~2 分钟：

  1. 在服务商控制台的安全组/防火墙里放行 SSH 端口和节点端口（默认 TCP 443）。
  2. 控制台 → 节点 → 添加节点 → 「一键部署新服务器」。复制第 1 步显示的授权命令，用 root 登录新服务器运行一次。它只添加一把公钥，并限制只能从订阅服务器登录。
  3. 填写节点名称（显示在用户客户端里，如 HK-01）、服务器 IP、SSH 端口、节点域名前缀，并在下拉框选择主域名（如 hk1 + .{{BASE_DOMAIN}}）。主域名在「域名管理」里增删，见第 4 节。
  4. 点开始，在日志窗口里看进度：设置 DNS → 申请证书 → 安装 sing-box → 写入配置 → 验证。

完成后节点自动加入所有人的订阅，现有节点不受影响。部署失败可以直接重试，已经完成的步骤会自动跳过。

最后一步提示「TLS 验证未通过」不一定是失败：订阅服务器在国内，直连境外节点可能被干扰。用客户端实际连一下确认即可。

接入已有节点

服务器上已经自己配好了 sing-box 和 AnyTLS 入站时使用。同样先运行授权命令，然后在「接入已有 sing-box」里填写信息。节点上原有的 AnyTLS 用户会被替换成控制台的账号列表。

移除节点

节点卡片上的 移除 只是让它不再出现在订阅中、不再受管理。服务器上的 sing-box、DNS 解析和证书都保持原样，需要的话请自行清理或退订服务器。最后一个节点不能移除。

状态卡片怎么看

项目含义

升级 sing-box

节点卡片显示黄色「可升级到 x.y.z」时，可以点卡片上的升级按钮，或点 版本管理 一次选择多个节点、选择目标版本（也能回退到旧版本）。

  • 升级会自动识别安装方式（deb / rpm / 程序文件），从 sing-box 官方 GitHub 下载。
  • 升级前备份配置和旧程序；新版本校验配置失败或启动失败会自动回滚。
  • 每个节点升级时会重启一次，建议在用户少的时候操作。

4. 证书与域名

证书谁负责续期续期后
{{SUB_DOMAIN}}（订阅/控制台）订阅服务器的 certbot，Cloudflare DNS 验证自动重载 Nginx

接入的节点（外部配置）节点自己需要确保续期后重启 sing-box，可安装仓库 contrib/certbot-restart-sing-box.sh 作为续期钩子

节点域名管理（多个域名与 Token）

控制台 → 节点 → 域名管理 可以添加多个主域名，每个主域名配一个自己的 Cloudflare Token。一键部署节点时，在「节点域名」后面的下拉框选择用哪个主域名（如 hk1 + .example.com）。

  • 添加：域名的 DNS 必须托管在 Cloudflare。为它单独创建 Token（Edit zone DNS 模板，Zone Resources 只选这个域名），在弹窗里填写后点「验证并添加」。保存前会检查能否访问域名、读取和编辑 DNS（创建一条 _sbm-check 测试 TXT 记录并立即删除），不通过不会保存。
  • 检测：只读检查现有 Token 是否仍然有效。Token 过期或被删后，自动续期也会失败，建议偶尔检测一下。
  • 更换 Token：验证通过后覆盖原 Token 文件，已签发证书的续期自动使用新 Token，不用改别的。
  • 设为默认：部署表单默认选中的域名，命令行部署不带 --zone 时也用它。
  • 删除：只能删除没有被订阅域名和节点使用的域名；只删除订阅服务器上保存的 Token，不会动 Cloudflare 里的 Token 和 DNS 记录。

Token 保存为仅 root 可读的文件：安装时设置的主域名（{{BASE_DOMAIN}}）沿用 /etc/letsencrypt/cloudflare.ini，之后添加的在 /etc/letsencrypt/sbm-cf/<域名>.ini。控制台和接口都不会再显示 Token 内容。Token 不会下发到节点。

接入节点的证书：如果节点自己用 certbot 续期证书，续期后需要重启 sing-box 才会加载新证书。把仓库里的 contrib/certbot-restart-sing-box.sh 放到节点的 /etc/letsencrypt/renewal-hooks/deploy/ 并加执行权限即可：它只在续期的证书正被 sing-box 使用时，先校验配置再重启。用 standalone 方式续期的节点还需要保持入站 80 端口可访问。
查看钩子执行记录：在节点上运行 journalctl -t certbot-sing-box。

Token 失效或被删除时，重新在 Cloudflare 创建，然后在「域名管理」里点该域名的 更换 Token 即可（命令行：sudo sbm domain token {{BASE_DOMAIN}}）。

5. 命令行参考

在你的电脑上 ssh ubuntu@{{MANAGER_IP}} 登录订阅服务器后使用，所有命令都需要 sudo。命令行和网页控制台共用同一份数据和同一把锁，可以混用。

# 用户
sudo sbm user list                         # 列出用户、状态、账号池
sudo sbm user add alice --note "张三的手机"   # 新增（不重启）
sudo sbm user show alice                   # 查看链接
sudo sbm user config alice                 # 查看订阅配置概览（节点、代理组、分流规则）
sudo sbm user config alice --format clash  # 实际下发的原文：singbox | clash | uri
sudo sbm user disable alice [--now]        # 停用；--now 立即踢下线
sudo sbm user enable alice
sudo sbm user del alice [--now]            # 删除；--now 立即踢下线
sudo sbm user reset alice [--later]        # 重置；默认立即生效，--later 凌晨生效

# 流量统计
sudo sbm traffic                           # 本月各用户流量
sudo sbm traffic collect -v                # 立即采集一次

# 账号池与维护
sudo sbm pool                              # 账号池、待清理账号、下次维护时间
sudo sbm sync                              # 立即维护（只有变化的节点会重启）

# 节点
sudo sbm node list
sudo sbm node pubkey                       # 授权命令
sudo sbm node deploy HK-01 --host 203.0.113.10 --sub hk1 [--zone example.com] [--ssh-port 22] [--port 443]
sudo sbm node attach HK-01 --host 203.0.113.20 [--inbound-tag anytls-in]
sudo sbm node del HK-01
sudo sbm node versions                     # 各节点版本与最新版
sudo sbm node upgrade --all                # 或 sbm node upgrade HK-01 --version 1.14.3
sudo sbm status                            # 节点运行状态

# 节点域名与 Cloudflare Token
sudo sbm domain list                       # 域名、默认、用途
sudo sbm domain add example.com --note 备用  # 随后提示输入 Token（不显示），验证通过才保存
sudo sbm domain check example.com          # 只读检测 Token
sudo sbm domain token example.com          # 更换 Token
sudo sbm domain default example.com        # 设为默认
sudo sbm domain del example.com            # 删除未使用的域名
注意：如果你自己的电脑也通过某个节点上网，在命令行执行会重启节点的操作时 SSH 会断开，可能导致操作中断。这类操作建议用网页控制台，或用 sudo systemd-run --unit sbm-job sbm ... 放到后台执行，再用 journalctl -u sbm-job 查看结果。

6. 故障排查

控制台操作后提示「连接中断」

你的电脑正好通过刚重启的节点上网，响应没收到。操作在服务器上通常已完成，页面会在 4 秒后自动刷新确认。

某个用户连不上

  1. 确认用户状态是「启用」。
  2. 让对方在客户端更新订阅，再换一个节点试试。
  3. 看节点卡片是否「已停止」或「待同步」；有「待同步」就点 同步节点。
  4. 对方客户端版本太旧可能不支持 AnyTLS，让对方升级到最新版。
  5. 仍不行就 重置 该用户，把新的使用说明页发过去。

所有人都连不上某个节点

  • 卡片显示「无法连接」：服务器宕机、IP 被封或服务商安全组变更，登录服务商控制台检查。
  • 卡片显示「已停止」：在节点上运行 journalctl -u sing-box -n 50 查看原因；常见是证书过期。
  • 节点 IP 被封时，可以换一台服务器重新「一键部署」，再「移除」旧节点。

订阅链接打开是 404

链接对应的用户已被停用、删除或重置。到控制台查看该用户的最新链接。

控制台打不开

  • 检查云服务商安全组是否放行 TCP {{SUB_PORT}}。
  • 登录框反复弹出：密码错误，重设管理员密码：ssh -t ubuntu@{{MANAGER_IP}} "sudo htpasswd -B /etc/nginx/sbm-admin.htpasswd admin"
  • 页面显示 502：管理后台服务异常，运行 sudo systemctl restart sbm-web，并用 journalctl -u sbm-web -n 50 查看原因。

CentOS 7 节点

CentOS 7 的 systemd 太旧，部署时会自动添加兼容配置，让 sing-box 以 root 运行。CentOS 7 已停止维护，建议有条件时重装为 Debian 12 / Ubuntu 24.04 后重新部署。

7. 备份与恢复

重要数据都在订阅服务器上，节点可以随时重新部署。建议每次较大改动后备份一次：

sudo tar czf ~/sbm-backup-$(date +%F).tar.gz \
  /etc/sbm /etc/letsencrypt /root/.ssh/sbm_node /root/.ssh/sbm_node.pub \
  /usr/local/bin/sbm /opt/sbm-web /etc/nginx/sites-available/sub.conf \
  /etc/nginx/sbm-admin.htpasswd /etc/systemd/system/sbm-web.service \
  /etc/systemd/system/sbm-maintain.service /etc/systemd/system/sbm-maintain.timer \
  /etc/systemd/system/sbm-traffic.service /etc/systemd/system/sbm-traffic.timer \
  /usr/local/share/sbm

然后在你自己的电脑上下载保存（PowerShell）：

scp ubuntu@{{MANAGER_IP}}:~/sbm-backup-*.tar.gz .
文件内容
/etc/sbm/users.json用户、密码、订阅令牌（最重要）
/etc/sbm/creds.json账号池、待清理账号、流量统计编号
/etc/sbm/traffic.db流量统计数据
/etc/sbm/config.json订阅域名、节点列表
/root/.ssh/sbm_node管理节点用的 SSH 私钥
/etc/letsencrypt/证书和 Cloudflare Token
备份文件里有所有用户的密码、SSH 私钥和 Cloudflare Token，请妥善保管，不要上传到网盘公开目录或发给他人。

恢复：在新服务器上解压到根目录（sudo tar xzf 备份.tar.gz -C /），安装 nginx certbot python3-certbot-dns-cloudflare python3-qrcode jq，启用 Nginx 站点和 sbm-web / sbm-maintain.timer 服务，再把 {{SUB_DOMAIN}} 解析到新 IP。各节点的授权限制了只能从 {{MANAGER_IP}} 登录，换了订阅服务器 IP 需要在每个节点上重新运行授权命令。

8. 安全建议

  • 控制台地址和管理员密码只自己掌握；定期更换管理员密码。
  • 每个人用自己的账号，不要多人共用。有人离开就删除，链接外泄就重置。
  • 各服务器的 root 密码不要通过聊天工具发送；已经发出过的密码请尽快修改（ssh -t root@节点IP passwd）。
  • 节点和订阅服务器保持系统更新；CentOS 7 等停止维护的系统尽早更换。
  • 请自行评估服务器所在地法规和云服务商条款的风险。
